# Interface iteration

## Screenshot audit

The supplied Q192 screenshots show two failures: a hover explanation spans and
clips across the footer, and an oversized animation switch dominates its panel.
The pasted review also gives five results and several paragraphs of caveats the
same visual priority.

1. **Review:** replace the default text report with five grouped comparisons.
   Shared zero-based scales compare Your policy, Hold and Model benchmark within
   each measure. Values and direction labels accompany color; color is not the
   only identifier. Add the benchmark's price/jobs difference as a short takeaway.
2. **Detail:** put methodology and challenge rules behind named buttons. Keep
   exact source values, qualifications and scoring definitions available there.
3. **Hover:** wrap native help within 340 logical pixels, bounded by the viewport.
   Preserve zero delay, control behavior and assistive descriptions. Use short
   challenge hints rather than putting the complete rulebook in a hover popup.
4. **Chrome:** compact the animation switch and shorten routine-follow-up copy.
   Keep the existing teal/mint/gold identity and Godot layout rather than spending
   this iteration on an engine migration.

## Evidence and limits

Isolated native ARM64/headless checks cover value parity, shared scales,
read-only review, disclosures, keyboard navigation, small report bounds and
actual engine-created tooltip popups. A background native source preview was
inspected with Computer Use: graphical review, End scrolling and Escape focus
restoration. The preview used private storage and exited automatically; no
player save or running player app was used.

This pass changes presentation, not economic coefficients or difficulty.
Whole-dashboard hierarchy, preview graphics and concise Help navigation remain
useful subsequent design work; this is not whole-game usability acceptance.

## Completed outcome drivers

The routine-stop footer no longer appends the equation dump. Five signed,
zero-centered bars sit beside the history charts; the header names the completed
interval, gap change and common scale. Positive means an upward gap contribution,
not a welfare gain. Tiny values retain direction without scientific notation or
full-width numerical-noise bars. Details retains the complete equation explanation
and its attribution limits.

The strip uses completed history only and makes no forecasts or economic steps.
Valid refreshes keep keyboard focus; New/Load and invalid results clear stale
attribution. The graph stays out of the pinned footer so compact-window adoption
remains reachable. Economic coefficients and save format are unchanged.

## Current conditions and compact outcomes

Current canonical shock title and policy dilemma now lead the briefing instead
of being buried after repeated market/public narration. The summary retains
current demand/supply/gap, long expectations, hardship, promise delivery and
funding essentials. Refinancing is capped by maturing principal; eligible need
and haircut/eligibility-adjusted secured value use current GDP. The original
full briefing remains unchanged behind keyboard-accessible Details.

Outcome feedback uses two concise lines, plus a funding line only when needed.
Multi-quarter changes name their full interval; rate, funding and promise refer
to the final meeting. Final-meeting promise evaluation no longer disappears
when a routine segment began before the first announcement. Score-point units
and rounding bounds remain explicit. Policy controls use tighter spacing without
smaller fonts, and driver-chart scale is explicitly labelled.

## Topic-based Help

Help now opens with a short play loop and six named topics. The existing complete
help assembly is retained verbatim; each nonempty paragraph appears exactly once
in the topic reference. Unknown future paragraphs remain reachable in the final
topic. Staff estimates, diagnostic benchmarks, scenario-specific scoring, units,
negative-rate limits and settlement recovery were not paraphrased away.

The chooser and read-only native text share one existing ReportDialog. Tab links
topics, text and Close; native arrows/Return choose a topic. Escape cancels an open
menu before closing the report. Selection resets the reading position, and the
assistive description tracks the selected topic. The container, not the text
widget, owns the report minimum so small windows can wrap properly.

Evidence: 89 focused checks cover both scoring branches, exact paragraph coverage,
read-only access, purity and 320/640-pixel fitting. Full UI/keyboard suites pass,
including real menu key dispatch. One inherited keyboard fixture used a 64×64
headless parent; it now supplies a realistic Help-only headless canvas while
keeping the Page Down assertion. Native previews are never resized by that test.
A private background source preview was inspected with Computer Use: Shift+Tab,
Return/Down selection, menu Escape, Tab/Page Down scrolling, then report Escape
and rate-focus restoration. No career adoption occurred; this is source UI
validation, not an installed-binary or whole-game usability claim.

## Graphical challenge progress

Three target meters now show completed inflation misses, employment shortfalls
and eligible funding coverage. Each has a value, limit marker and explicit text
status; color is not the only cue. Cost meters show 0–2×limit, funding 0–100%, with
uncapped displayed values and precise boundary direction. The most binding of
career/recent constraints is shown, normalized by its actual limit. No data and
incomplete recovery windows are neutral, and practice has no score panel.

The footer retains a short persistent title/status. Details exposes the measures
and unchanged fictional scoring rules; an unobserved mean is not reported as
measured zero. No score, equation, policy tool or save format changed.

The first native preview placed the bottom of the meters behind the action bar.
Reducing the illustrative city viewport from 215 to 140 logical pixels fixed that
hierarchy without changing the asset. The final native geometry log confirms the
whole board fits the cockpit. A window-bounded compact-layout capture was
inspected; metric labels were then clarified to distinguish misses from rates.
Headless 1280×840 checks cover final label/status bounds and keyboard End reaches
the full real projection below the initial fold while Adopt remains pinned.

Qualification: 55 focused checks include exact 95% principal-boundary behavior,
recent/career selection, malformed clearing, both scorers, real current-information
career rendering and active-routine Enter/Details/Escape/no-later-adoption.
Full default game suite passed before final copy/layout refinements; final full UI,
compact, mandate and focused checks passed afterward. Broader validation exposed
stale Help-child assumptions in three tests and one stale refinancing label;
those assertions were repaired without relaxing their numeric/semantic checks.
Independent code/test and non-code visual reviews were completed. Source previews
used private storage; no player save or running player app was used.
