# Interface iteration

## Screenshot audit

The supplied Q192 screenshots show two failures: a hover explanation spans and
clips across the footer, and an oversized animation switch dominates its panel.
The pasted review also gives five results and several paragraphs of caveats the
same visual priority.

1. **Review:** replace the default text report with five grouped comparisons.
   Shared zero-based scales compare Your policy, Hold and Model benchmark within
   each measure. Values and direction labels accompany color; color is not the
   only identifier. Add the benchmark's price/jobs difference as a short takeaway.
2. **Detail:** put methodology and challenge rules behind named buttons. Keep
   exact source values, qualifications and scoring definitions available there.
3. **Hover:** wrap native help within 340 logical pixels, bounded by the viewport.
   Preserve zero delay, control behavior and assistive descriptions. Use short
   challenge hints rather than putting the complete rulebook in a hover popup.
4. **Chrome:** compact the animation switch and shorten routine-follow-up copy.
   Keep the existing teal/mint/gold identity and Godot layout rather than spending
   this iteration on an engine migration.

## Evidence and limits

Isolated native ARM64/headless checks cover value parity, shared scales,
read-only review, disclosures, keyboard navigation, small report bounds and
actual engine-created tooltip popups. A background native source preview was
inspected with Computer Use: graphical review, End scrolling and Escape focus
restoration. The preview used private storage and exited automatically; no
player save or running player app was used.

This pass changes presentation, not economic coefficients or difficulty.
Whole-dashboard hierarchy, preview graphics and concise Help navigation remain
useful subsequent design work; this is not whole-game usability acceptance.
